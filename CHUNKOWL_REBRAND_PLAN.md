# ChunkOwl rebrand plan

ChunkOwl is the chosen future brand; BlockWise is the historical and current public name. This plan does not establish trademark clearance or a purchased domain.

1. Inventory BlockWise references in HTML headings, navigation, footers, JavaScript, CSS, metadata, structured data, tests, documents, image names and accessibility labels. Preserve historical audit records and provenance.
2. In a separate reviewed change, update visible branding, titles, descriptions, Open Graph metadata and structured data consistently. Keep existing technical URLs and asset filenames until a real destination and migration plan exist.
3. Keep canonicals and sitemap entries pointing to working public URLs. If a future domain or repository path changes, plan redirects, update internal links and sitemap, and monitor indexing and broken links. GitHub Pages project-path changes may break old links; a repository rename does not by itself prove redirects cover every asset.
4. Retain the Google Search Console verification file. Verify ownership of any new URL-prefix property and submit its sitemap after deployment; a new domain or path can require new verification. Do not assume search rankings transfer immediately.
5. Test every page, asset, relative path, search, navigation, settings and mobile layout under the deployed project path. Review social previews, structured data and accessibility after rollout.
6. Stage the migration: inventory and review; make a reversible branch; test locally and in a preview; obtain owner approval; deploy; check old and new links and Search Console. Record a rollback commit and restore the prior working version if failures occur. Do not change DNS, hosting settings or repository name without separate approval.
